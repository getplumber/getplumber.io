This page is the field-by-field reference for the `gitlab.controls:` and `github.controls:` sections of `.plumber.yaml`. For each control it lists the YAML block, every field with its type and default, and the issues the control raises. For the three ways to write the file (no config, overlay, full config) see [Configuration](/docs/cli/configuration); for what each control checks and why it matters see the [Controls catalog](/docs/cli/controls); for the description and remediation of a finding see [Issues](/docs/cli/issues).

The defaults below are the values of the `plumber:default` baseline: what runs when you have no `.plumber.yaml`, what an overlay inherits, and what `plumber config generate` writes. They match the baseline shipped with Plumber v0.5.10. To see the baseline of the version you run, use `plumber config generate --output -` or `plumber config view`.

## How a control block works

**Where blocks live.** Every control is a block under `gitlab.controls.<name>` or `github.controls.<name>` in a schema `version: "2.0"` file. The block name is also the name you pass to `--controls` and `--skip-controls`, and the `controlName` of the block's findings in the JSON report.

**`enabled`.** Every block accepts `enabled: true | false`. When the block is missing, the effect depends on the mode: in an [overlay](/docs/cli/configuration#extended-configuration-recommended) (`extends: plumber:default`) a missing block inherits the baseline; in a [full configuration](/docs/cli/configuration#full-configuration) a missing block means the control does not run. A control that is off or absent is reported as `skipped`, never as passed.

**Lists replace, maps merge.** In an overlay, nested maps merge key by key, but a list you write replaces the baseline list entirely. Writing `tags: [nightly]` under `containerImageMustNotUseForbiddenTags` drops `latest`, `dev` and the other baseline tags: repeat the entries you want to keep. The two curated allowlists are the exception, see the next point.

**`includePlumberDefaults`.** The two allowlist controls, `containerImageMustComeFromAuthorizedSources` (`trustedUrls`) and `githubActionMustComeFromAuthorizedSources` (`trustedGithubActions`), carry an extra `includePlumberDefaults` boolean. With the default `true`, the entries you write are added to Plumber's curated list; with `false`, only your entries are trusted. The field only acts in overlay mode; a full configuration always uses exactly the list it contains. Run `plumber config resolve` to print the final unioned list.

**Unset means "not checked" on expectation fields.** Fields that describe the setting a project must have (`allowForcePush`, `codeOwnerApprovalRequired`, every field of the merge request settings controls) are only compared when you set them. Leaving one out asserts nothing about it. There is no way to expect the unsafe value.

**Some booleans are `true` when unset.** When you write a full configuration and omit one of these, Plumber behaves as if it were `true`: `detectInsecureDaemon`, `defaultBranchIsForbiddenVersion`, `includePlumberDefaults`, `trustGithubOfficialActions`, `trustSameOrgActions`, and the `enabled` of the three `securityJobsMustNotBeWeakened` sub-checks. Every other omitted boolean is `false`.

**Controls that need configuration.** Some controls assert nothing until they are given something to check (a list of tags, a set of required components, a minimum number of approvals). They are marked *needs configuration* below. In an overlay the baseline supplies that configuration; in a full configuration, `enabled: true` alone makes the control run and pass with nothing to check.

**`required` and `requiredGroups`.** The three "must include" controls (`pipelineMustIncludeComponent`, `pipelineMustIncludeTemplate`, `workflowMustIncludeRequiredActions`) take their requirement in one of two equivalent forms, never both:

- `required`, a boolean expression with `AND`, `OR` and parentheses. `AND` binds tighter than `OR`, so `a AND b OR c` reads `(a AND b) OR c`.
- `requiredGroups`, the same logic written out as a list of lists: the outer list is an OR, each inner list is an AND.

```yaml
# These two are equivalent
required: (templates/go/go AND templates/trivy/trivy) OR templates/full-go-pipeline
requiredGroups:
  - ["templates/go/go", "templates/trivy/trivy"]
  - ["templates/full-go-pipeline"]
```

**Severity is not configurable.** Each issue code carries a fixed severity (see [Issues](/docs/cli/issues)). Configuration decides whether a control runs and what it checks, not how a finding is graded.

**GitLab plan tiers.** Four GitLab controls and three fields read settings that only exist on a paid plan; they are tagged *Premium* or *Ultimate* below. On GitLab Free, enable only the controls your plan exposes.

**Validation.** Unknown control names and unknown fields produce a warning with a "did you mean" suggestion and are ignored. `plumber config validate` reports them without running a scan; `plumber analyze --fail-warnings` turns them into a failure.

## Controls on both providers

The same block, with the same fields, under `gitlab.controls` and `github.controls`. Where a default differs between providers, both are given.

### containerImageMustNotUseForbiddenTags

Flags container images referenced by a mutable tag, and, when digest pinning is required, any image not pinned by digest. Raises [ISSUE-102](/docs/use-plumber/issues/ISSUE-102) (medium) and [ISSUE-103](/docs/use-plumber/issues/ISSUE-103) (high). On by default. *Needs configuration.*

| Field | Type | Default | Description |
|---|---|---|---|
| `enabled` | boolean | `true` | Turns the control on. |
| `tags` | list of strings | `latest`, `dev`, `development`, `staging`, `main`, `master` | Tags considered mutable and therefore forbidden. |
| `containerImagesMustBePinnedByDigest` | boolean | `true` (unset: `false`) | When `true`, every image must be referenced by an immutable `@sha256:` digest. Takes precedence over `tags`: a version tag such as `alpine:3.19` is then also flagged (ISSUE-103). |

```yaml
containerImageMustNotUseForbiddenTags:
  enabled: true
  tags:
    - latest
    - dev
    - development
    - staging
    - main
    - master
  containerImagesMustBePinnedByDigest: true
```

### branchMustBeProtected

Checks that the branches matching `namePatterns` (and the default branch) are protected, and that their protection settings meet the expectations below. Raises [ISSUE-501](/docs/use-plumber/issues/ISSUE-501) (critical) when a branch is not protected and [ISSUE-505](/docs/use-plumber/issues/ISSUE-505) (high) when its settings are not compliant. On by default. *Needs configuration.* Needs an API token; without one the control abstains.

| Field | Type | Default | Description |
|---|---|---|---|
| `enabled` | boolean | `true` | Turns the control on. |
| `defaultMustBeProtected` | boolean | `true` | Also requires the project's default branch to be protected, whether or not it matches `namePatterns`. |
| `namePatterns` | list of strings | `main`, `master`, `release/*`, `production`, `dev` | Branch name patterns that must be protected. Wildcards are supported. |
| `allowForcePush` | boolean | `false` | Expectation: when `false`, force push must be disabled on the protected branch. |
| `codeOwnerApprovalRequired` | boolean | `false` | Expectation: when `true`, code owner approval must be required. *GitLab Premium.* |
| `minMergeAccessLevel` | integer | GitLab `30`, GitHub unset | Expectation: the minimum access level allowed to merge. GitLab access levels: `0` (No one, the strictest), `30` (Developer), `40` (Maintainer). Not used on GitHub. |
| `minPushAccessLevel` | integer | GitLab `40`, GitHub unset | Expectation: the minimum access level allowed to push. Same values. Not used on GitHub. |

On GitHub the control reads both classic branch protection and repository or organization rulesets covering the branch, and evaluates the stricter of the two.

```yaml
branchMustBeProtected:
  enabled: true
  defaultMustBeProtected: true
  namePatterns:
    - main
    - master
    - release/*
    - production
    - dev
  allowForcePush: false
  codeOwnerApprovalRequired: false
  minMergeAccessLevel: 30 # GitLab only, Developer
  minPushAccessLevel: 40 # GitLab only, Maintainer
```

### pipelineMustNotEnableDebugTrace

Flags a pipeline that sets a debug variable to a truthy value, which dumps every variable including masked secrets into the job log. Raises [ISSUE-203](/docs/use-plumber/issues/ISSUE-203) (critical). On by default. *Needs configuration:* there is no built-in list, the control only checks the variables you list.

| Field | Type | Default | Description |
|---|---|---|---|
| `enabled` | boolean | `true` | Turns the control on. |
| `forbiddenVariables` | list of strings | GitLab: `CI_DEBUG_TRACE`, `CI_DEBUG_SERVICES`. GitHub: `ACTIONS_STEP_DEBUG`, `ACTIONS_RUNNER_DEBUG` | Variable names that must not be set to `true` (`1` and `yes` also count on GitHub). |

```yaml
pipelineMustNotEnableDebugTrace:
  enabled: true
  forbiddenVariables:
    - CI_DEBUG_TRACE # GitLab
    - CI_DEBUG_SERVICES
```

### securityJobsMustNotBeWeakened

Flags security scanning jobs that are allowed to fail, whose rules were overridden to skip them, or that were made manual. Raises [ISSUE-410](/docs/use-plumber/issues/ISSUE-410) (critical). On by default. *Needs configuration:* the control checks only jobs matching `securityJobPatterns`, and counts as skipped when all three sub-checks are off.

| Field | Type | Default | Description |
|---|---|---|---|
| `enabled` | boolean | `true` | Turns the control on. |
| `securityJobPatterns` | list of strings | GitLab: `*-sast`, `secret_detection`, `container_scanning`, `*_dependency_scanning`, `gemnasium-*`, `dast`, `dast_*`, `license_scanning`. GitHub: `*codeql*`, `*dependency-review*`, `*trufflehog*`, `*gitleaks*`, `*osv-scanner*`, `*semgrep*`, `*trivy*`, `*snyk*`, `*-sast`, `*-sast-*`, `*-scan`, `*scan*`, `*-security`, `*-security-*`, `*-audit`, `*-audit-*`, `*secret*detect*`, `*detect*secret*` | Job name patterns treated as security jobs. Wildcards are supported. On GitHub the pattern is matched against `<workflow file name without extension>/<job id>`, for example `codeql/analyze`. |
| `allowFailureMustBeFalse.enabled` | boolean | GitLab `false`, GitHub `true` (unset: `true`) | Sub-check: the job must not carry `allow_failure: true` (GitLab) or `continue-on-error: true` (GitHub). Off on GitLab because GitLab's own security templates ship with `allow_failure: true`. |
| `rulesMustNotBeRedefined.enabled` | boolean | `true` (unset: `true`) | Sub-check: the job's `rules:` must not be overridden to `when: never` or `when: manual`. |
| `whenMustNotBeManual.enabled` | boolean | `true` (unset: `true`) | Sub-check: the job must not be `when: manual` (GitLab) or reachable only through a manual dispatch trigger (GitHub). |

```yaml
securityJobsMustNotBeWeakened:
  enabled: true
  securityJobPatterns:
    - "*-sast"
    - "secret_detection"
    - "container_scanning"
  allowFailureMustBeFalse:
    enabled: false # GitLab baseline; true on GitHub
  rulesMustNotBeRedefined:
    enabled: true
  whenMustNotBeManual:
    enabled: true
```

### pipelineMustNotExecuteUnverifiedScripts

Flags scripts downloaded and executed in one go (`curl | bash`, `wget | sh`) from a URL that is not trusted. Raises [ISSUE-411](/docs/use-plumber/issues/ISSUE-411) (high). On by default.

| Field | Type | Default | Description |
|---|---|---|---|
| `enabled` | boolean | `true` | Turns the control on. |
| `trustedUrls` | list of strings | empty | URL patterns that do not trigger a finding. Wildcards are supported. Matching is host-precise: `https://example.com/*` does not cover a subdomain. |

```yaml
pipelineMustNotExecuteUnverifiedScripts:
  enabled: true
  trustedUrls:
    - https://internal-artifacts.example.com/*
```

### pipelineMustNotUseDockerInDocker

Flags jobs that run a Docker-in-Docker service, and optionally an insecure daemon configuration in those jobs. Raises [ISSUE-412](/docs/use-plumber/issues/ISSUE-412) (high) and [ISSUE-413](/docs/use-plumber/issues/ISSUE-413) (high). On by default.

| Field | Type | Default | Description |
|---|---|---|---|
| `enabled` | boolean | `true` | Turns the control on. |
| `detectInsecureDaemon` | boolean | `true` (unset: `true`) | Also flags an insecure daemon configuration in a DinD job: an empty `DOCKER_TLS_CERTDIR` or a plaintext `DOCKER_HOST` such as `tcp://docker:2375` (ISSUE-413). |

```yaml
pipelineMustNotUseDockerInDocker:
  enabled: true
  detectInsecureDaemon: true
```

### externalRefsMustNotCollide

Flags an include (GitLab) or an action reference (GitHub) whose ref exists both as a tag and as a branch in the upstream repository, so what runs is ambiguous. Raises [ISSUE-402](/docs/use-plumber/issues/ISSUE-402) (medium). On by default. Needs an API token; without one the control abstains. No field beyond `enabled`.

```yaml
externalRefsMustNotCollide:
  enabled: true
```

## GitLab controls

Blocks under `gitlab.controls` only.

### containerImageMustComeFromAuthorizedSources

Flags a job image that does not come from a trusted registry or publisher. Raises [ISSUE-101](/docs/use-plumber/issues/ISSUE-101) (high). On by default.

| Field | Type | Default | Description |
|---|---|---|---|
| `enabled` | boolean | `true` | Turns the control on. |
| `trustDockerHubOfficialImages` | boolean | `true` (unset: `false`) | Trusts Docker Hub official images such as `nginx` or `alpine`. |
| `trustedUrls` | list of strings | Plumber's curated list (about 90 entries) | Trusted registry URLs or image patterns. Wildcards are supported. Baseline entries include the project registry (`$CI_REGISTRY_IMAGE:*`, `$CI_REGISTRY/*`), `registry.gitlab.com/security-products/*`, common Docker Hub publishers, and selected namespaces on `ghcr.io`, `quay.io`, `gcr.io` and `mcr.microsoft.com`. |
| `includePlumberDefaults` | boolean | `true` | Overlay mode only: `true` adds your `trustedUrls` to the curated list, `false` trusts only your entries. |

Prefer namespace patterns such as `ghcr.io/myorg/*` over host-wide wildcards such as `ghcr.io/*`, which trust every publisher on that host.

```yaml
containerImageMustComeFromAuthorizedSources:
  enabled: true
  trustDockerHubOfficialImages: true
  includePlumberDefaults: true
  trustedUrls:
    - $CI_REGISTRY_IMAGE:*
    - registry.example.com/platform/*
```

### cicdVariablesMustBeProtected

Flags a CI/CD variable in the project settings that is not marked protected. Raises [ISSUE-201](/docs/use-plumber/issues/ISSUE-201) (medium). Off by default. Needs a token with read access to the project variables; a `401`/`403` is reported as not evaluable, never as a pass. No field beyond `enabled`.

```yaml
cicdVariablesMustBeProtected:
  enabled: false
```

### cicdVariablesMustBeMasked

Flags a CI/CD variable in the project settings that is not masked. Raises [ISSUE-202](/docs/use-plumber/issues/ISSUE-202) (medium). Off by default. Same token requirement as above. GitLab cannot mask values shorter than 8 characters; those are still flagged. No field beyond `enabled`.

```yaml
cicdVariablesMustBeMasked:
  enabled: false
```

### mergeRequestApprovalRulesMustRequireMinimumApprovals

Flags a merge request approval rule covering all protected branches that requires fewer approvals than the minimum. Raises [ISSUE-502](/docs/use-plumber/issues/ISSUE-502) (high). Off by default. *Needs configuration.* *GitLab Premium.*

| Field | Type | Default | Description |
|---|---|---|---|
| `enabled` | boolean | `false` | Turns the control on. |
| `minimumRequiredApprovals` | integer | `1` | The fewest approvals a rule covering all protected branches must require. Unset asserts nothing. |

```yaml
mergeRequestApprovalRulesMustRequireMinimumApprovals:
  enabled: true
  minimumRequiredApprovals: 2
```

### mergeRequestApprovalRulesMustCoverAllProtectedBranches

Flags a project where no approval rule targets all protected branches. Raises [ISSUE-504](/docs/use-plumber/issues/ISSUE-504) (high). Off by default. *GitLab Premium:* on GitLab Free the approvals API returns no rule, so the control would fire on every project. No field beyond `enabled`.

```yaml
mergeRequestApprovalRulesMustCoverAllProtectedBranches:
  enabled: true
```

### mergeRequestApprovalSettingsMustBeCompliant

Compares the project's merge request approval settings with the expectations you set. Raises [ISSUE-503](/docs/use-plumber/issues/ISSUE-503) (high). Off by default. *Needs configuration.* *GitLab Premium.* Every expectation is optional: a field you leave out (or set to `false`) is not checked.

| Field | Type | Default | Description |
|---|---|---|---|
| `enabled` | boolean | `false` | Turns the control on. |
| `preventApprovalByAuthor` | boolean | unset | Expectation: authors cannot approve their own merge requests. |
| `preventApprovalsByCommitters` | boolean | unset | Expectation: users who committed to a merge request cannot approve it. |
| `preventEditingApprovalRulesInMR` | boolean | unset | Expectation: approval rules cannot be edited in a merge request. |
| `requireReAuthToApprove` | boolean | unset | Expectation: approving requires re-authentication (password or SAML). |
| `behaviorWhenCommitIsAdded` | string | unset | Expectation: the minimum strictness when a commit is added to an open merge request. One of `keep_approvals`, `remove_approvals_by_code_owners`, `remove_all_approvals`, from least to most strict; a stricter project setting passes. Any other value is a configuration error. |

```yaml
mergeRequestApprovalSettingsMustBeCompliant:
  enabled: true
  preventApprovalByAuthor: true
  preventApprovalsByCommitters: true
  preventEditingApprovalRulesInMR: true
  requireReAuthToApprove: true
  behaviorWhenCommitIsAdded: remove_all_approvals
```

### mergeRequestSettingsMustBeCompliant

Compares the project's merge request settings with the expectations you set, field by field, for exact equality. Raises [ISSUE-506](/docs/use-plumber/issues/ISSUE-506) (medium). Off by default. *Needs configuration.* Every field is optional: a field you leave out is not checked.

| Field | Type | Default | Description |
|---|---|---|---|
| `enabled` | boolean | `false` | Turns the control on. |
| `mergeMethod` | string | unset | Expected merge method: `merge`, `ff` or `rebase_merge`. |
| `squashOption` | string | unset | Expected squash setting: `never`, `always`, `default_on` or `default_off`. |
| `mergePipelinesEnabled` | boolean | unset | Expected "merged results pipelines" setting. *GitLab Premium.* |
| `mergeTrainsEnabled` | boolean | unset | Expected "merge trains" setting. *GitLab Premium.* |
| `allowMergeOnSkippedPipeline` | boolean | unset | Expected "allow merge when the pipeline is skipped" setting. |
| `resolveOutdatedDiffDiscussions` | boolean | unset | Expected "automatically resolve outdated diff discussions" setting. |
| `printingMergeRequestLinkEnabled` | boolean | unset | Expected "show the merge request link when pushing" setting. |
| `removeSourceBranchAfterMerge` | boolean | unset | Expected "delete source branch after merge" default. |

```yaml
mergeRequestSettingsMustBeCompliant:
  enabled: true
  mergeMethod: ff
  squashOption: default_on
  allowMergeOnSkippedPipeline: false
  removeSourceBranchAfterMerge: true
```

### projectMustHaveSecurityPolicySource

Checks that the project is linked to a security policy project, optionally a specific one. Raises [ISSUE-601](/docs/use-plumber/issues/ISSUE-601) (critical). Off by default. *GitLab Ultimate.*

| Field | Type | Default | Description |
|---|---|---|---|
| `enabled` | boolean | `false` | Turns the control on. |
| `expectedProjectId` | integer | unset | The numeric ID the linked policy project must have. Unset only requires that some policy project is linked. |
| `expectedProjectPath` | string | unset | The full `namespace/project` path the linked policy project must have, compared case-insensitively. Ignored when `expectedProjectId` is also set. |

```yaml
projectMustHaveSecurityPolicySource:
  enabled: true
  expectedProjectPath: my-group/security-policy-project
```

### pipelineMustNotIncludeHardcodedJobs

Flags jobs defined directly in `.gitlab-ci.yml` instead of coming from an included template or component. Raises [ISSUE-401](/docs/use-plumber/issues/ISSUE-401) (medium). Off by default, because without a components strategy it flags most jobs. No field beyond `enabled`.

```yaml
pipelineMustNotIncludeHardcodedJobs:
  enabled: false
```

### includesMustBeUpToDate

Flags an included template or component pinned to a version older than the latest available. Raises [ISSUE-403](/docs/use-plumber/issues/ISSUE-403) (low). On by default. No field beyond `enabled`.

```yaml
includesMustBeUpToDate:
  enabled: true
```

### includesMustNotUseForbiddenVersions

Flags an include pinned to a mutable ref. Raises [ISSUE-404](/docs/use-plumber/issues/ISSUE-404) (medium). On by default. *Needs configuration.*

| Field | Type | Default | Description |
|---|---|---|---|
| `enabled` | boolean | `true` | Turns the control on. |
| `forbiddenVersions` | list of strings | `latest`, `~latest`, `main`, `master`, `HEAD` | Version patterns considered forbidden. |
| `defaultBranchIsForbiddenVersion` | boolean | `true` (unset: `true`) | Also forbids the included project's default branch, whatever its name. Set `false` to allow includes pinned to it. |

```yaml
includesMustNotUseForbiddenVersions:
  enabled: true
  forbiddenVersions:
    - latest
    - "~latest"
    - main
    - master
    - HEAD
```

### releaseWorkflowsMustNotRestoreUntrustedCache

Flags a release or publish job that restores a build cache which a pull request could have poisoned. A job has release intent when it uses one of `publishActions` or runs a command matching `publishScriptPatterns`; it restores a cache when it uses one of `cacheActions` in a restoring mode. Raises [ISSUE-705](/docs/use-plumber/issues/ISSUE-705?p=github) (high). On by default. *Needs configuration.*

| Field | Type | Default | Description |
|---|---|---|---|
| `enabled` | boolean | `true` | Turns the control on. |
| `publishActions` | list of strings | `pypa/gh-action-pypi-publish`, `JS-DevTools/npm-publish`, `gradle/publish-plugin`, `softprops/action-gh-release`, `ncipollo/release-action`, `goreleaser/goreleaser-action`, `crazy-max/ghaction-docker-buildx`, `changesets/action` | `uses:` prefixes that mark a job as a release job. |
| `cacheActions` | list of objects | 10 entries, listed below | The inventory of cache-restoring actions and how each decides to restore. |
| `cacheActions[].action` | string | required | The `uses:` prefix, for example `actions/setup-go`. |
| `cacheActions[].mode` | string | required | `always` (restores whenever present), `default` (restores unless `disableInput` is set to `disableValue`) or `opt-in` (restores only when `enableInput` is set). |
| `cacheActions[].disableInput` | string | unset | `default` mode: the `with:` input that turns caching off. |
| `cacheActions[].disableValue` | boolean | unset | `default` mode: the value of `disableInput` that turns caching off. |
| `cacheActions[].enableInput` | string | unset | `opt-in` mode: the `with:` input that turns caching on. |
| `cacheActions[].enableContains` | string | unset | `opt-in` mode: additionally requires the value of `enableInput` to contain this substring, case-insensitively. |
| `publishScriptPatterns` | list of strings | 12 regular expressions covering `npm`/`pnpm`/`yarn`/`bun publish`, `cargo publish`, `twine upload`, `poetry publish`, `gh release create`, `goreleaser release`, `semantic-release`, Gradle `publish`, Maven `deploy`, `dotnet nuget push`, `gem push`, `docker push` | Shell commands that mark a job as a release job even under a plain push or tag trigger. |
| `publishScriptExcludePatterns` | list of strings | `(?i)--dry-run`, `(?i)publishToMavenLocal` | Regular expressions; a run block matching one is not a release, even if it also matches `publishScriptPatterns`. |
| `allowedJobs` | list of strings | empty | Globs on `<workflow file>/<job id>`; a matching job is exempt. |

```yaml
releaseWorkflowsMustNotRestoreUntrustedCache:
  enabled: true
  publishActions:
    - pypa/gh-action-pypi-publish
    - softprops/action-gh-release
    - goreleaser/goreleaser-action
  cacheActions:
    - { action: actions/cache, mode: always }
    - { action: actions/cache/restore, mode: always }
    - { action: Swatinem/rust-cache, mode: always }
    - { action: actions/setup-go, mode: default, disableInput: cache, disableValue: false }
    - { action: gradle/actions/setup-gradle, mode: default, disableInput: cache-disabled, disableValue: true }
    - { action: actions/setup-node, mode: opt-in, enableInput: cache }
    - { action: actions/setup-python, mode: opt-in, enableInput: cache }
    - { action: actions/setup-java, mode: opt-in, enableInput: cache }
    - { action: pnpm/action-setup, mode: opt-in, enableInput: cache }
    - { action: docker/build-push-action, mode: opt-in, enableInput: cache-from, enableContains: type=gha }
  publishScriptPatterns:
    - '(?i)(npm|pnpm|yarn|bun)\s+publish'
    - '(?i)gh\s+release\s+create'
  publishScriptExcludePatterns:
    - '(?i)--dry-run'
  allowedJobs:
    - "release-docs/*"
```
