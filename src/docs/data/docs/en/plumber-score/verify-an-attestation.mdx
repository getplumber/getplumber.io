## Two things to verify

An [official organization](/docs/plumber-score/official-organizations)'s page rests on two signatures. The organization attestation is signed by Plumber with the key on [Keys](/docs/plumber-score/keys). Each repository's row rests on the Sigstore bundle its own GitHub Actions job produced, which needs no Plumber key at all.

Both checks run offline with [cosign](https://github.com/sigstore/cosign) v3. The commands below are the ones Plumber's own CI runs on every build. They use the `getplumber` organization as the example; replace the names with the organization and repository you check.

## The organization attestation

Download the view the attestation signs, the attestation, and the key:

```bash
curl -O https://score.getplumber.io/github.com/getplumber/view.json
curl -O https://score.getplumber.io/github.com/getplumber/attestation.json
curl -O https://getplumber.io/plumber-score/plumber-score.pub
cosign verify-blob-attestation --key plumber-score.pub \
  --type https://getplumber.io/attestation/org/v1 \
  --bundle attestation.json view.json
```

`Verified OK` means the view file you downloaded is byte for byte the one Plumber signed, the signature is Plumber's, and the Rekor log holds it. The attestation is an in-toto statement: its `subject` is the sha256 of `view.json`, its `predicate` restates the organization, the grade, the shares and every repository's row.

To read the signed statement:

```bash
jq -r '.dsseEnvelope.payload' attestation.json | base64 -d | jq .
```

## One repository's row

A row's provenance comes from GitHub, not from Plumber. The repository attestation carries the Sigstore bundle the job produced and names the exact report bytes it signed:

```bash
curl -O https://score.getplumber.io/github.com/getplumber/plumber-platform/attestation.json
curl -O https://score.getplumber.io/github.com/getplumber/plumber-platform/attestation.report.json
jq -r '.predicate.sourceBundle' attestation.json > source-bundle.json
cosign verify-blob --bundle source-bundle.json \
  --certificate-identity-regexp 'https://github.com/getplumber/plumber-platform/\.github/workflows/.+' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  attestation.report.json
```

`Verified OK` means a GitHub Actions job of that repository, running one of its own workflow files, signed exactly these report bytes. The certificate inside the bundle names the commit, the workflow path and the run; the organization attestation restates those fields in the row's `certificateIdentity`.

## What a verified row does not say

The signature proves where the report came from. It does not prove the report is a correct analysis. Plumber adds that assurance by checking the workflow that produced the push against the [locked workflow](/docs/plumber-score/locked-workflow) and the committed `.plumber.yaml`. A row marked `verified` passed those checks too. The organization page shows every check with its outcome.

cosign v2 can run the same commands with `--new-bundle-format` added before the `--bundle` argument.
